# Переход на рабочие аккаунты и корпоративную инфраструктуру

Инструкция начинается с безопасной локальной проверки рабочих аккаунтов. После неё тот же
набор настроек переносится на корпоративный сервер. Секретные значения нельзя присылать в чат,
вставлять в скриншоты или сохранять в Git.

## 1. Что требуется от владельца сервиса сейчас

Подготовьте четыре вещи:

1. Рабочего Telegram-бота, созданного через `@BotFather`.
2. Отдельный Telegram-аккаунт, от имени которого Telethon читает публичные каналы.
3. `api_id` и `api_hash` этого аккаунта с `my.telegram.org`.
4. Рабочий ключ OpenRouter с установленным лимитом расходов.

Дополнительно нужно выбрать способ допуска сотрудников к внутреннему боту. Текущая локальная
версия принимает команды любого пользователя, который найдёт username бота. До рабочего запуска
нужно добавить один из вариантов: список разрешённых Telegram ID в админке или одноразовые коды
приглашения. Рекомендуемый вариант — одноразовые коды приглашения с возможностью отозвать доступ
в админке: он не требует заранее собирать Telegram ID и не превращает ежедневную работу бота в
ручной процесс.

## 2. Создать рабочего бота

1. Откройте в Telegram официальный аккаунт `@BotFather`.
2. Отправьте `/newbot`.
3. Введите отображаемое имя бота.
4. Введите свободный username, который заканчивается на `bot`.
5. Сохраните выданный токен в менеджер паролей. Не отправляйте его в чат.
6. Через команды BotFather при желании задайте фотографию, краткое описание и полное описание.
7. Пока не рекламируйте username сотрудникам: сначала выполняется локальная приёмка и добавляется
   ограничение доступа.

От вас мне можно сообщить только username бота. Токен мне передавать не нужно.

## 3. Подготовить рабочий аккаунт Telethon

1. Используйте отдельный номер телефона и отдельный Telegram-аккаунт организации.
2. Включите двухэтапную аутентификацию Telegram и сохраните пароль в менеджере паролей.
3. Войдите этим аккаунтом на `https://my.telegram.org`.
4. Откройте **API development tools** и создайте приложение.
5. Сохраните `App api_id` и `App api_hash` в менеджер паролей.
6. Подпишите аккаунт на закрытые каналы, если они будут источниками. Для публичных каналов
   подписка обычно не обязательна, но она упрощает стабильное разрешение источников.

Код входа Telegram и пароль двухэтапной аутентификации вводятся только в PowerShell при создании
сессии. Их не нужно сохранять в конфигурационном файле.

## 4. Подготовить OpenRouter

1. Создайте отдельный API-ключ для рабочего сервиса либо оставьте текущий ключ, если он уже
   выделен только этому проекту.
2. Установите на стороне OpenRouter предел расходов.
3. Определите внутренний месячный предел приложения. На старте в шаблоне стоит `$25`;
   значение можно изменить через `AI_MONTHLY_BUDGET_USD`, а затем через админку вести месячные
   бюджеты.
4. Сохраните ключ в менеджер паролей и не присылайте его в чат.

Модели с идентификаторами вида `openai/...` всё равно вызываются через OpenRouter; поставщиком
запросов остаётся OpenRouter.

## 5. Создать отдельный локальный файл рабочих секретов

Откройте новый PowerShell и выполните команды по одной:

```powershell
cd "C:\Users\Vladislavv\Documents\ChatGPT\AI-дайджесты бот"
Copy-Item .\config\working-accounts-env.ps1.example .\var\working-accounts-env.ps1
notepad .\var\working-accounts-env.ps1
```

В Блокноте заполните значения между кавычками:

- `TELEGRAM_SOURCE_API_ID` — только цифры из `my.telegram.org`;
- `TELEGRAM_SOURCE_API_HASH` — секретный hash из `my.telegram.org`;
- `TELEGRAM_SOURCE_PHONE` — номер с `+` и кодом страны;
- `OPENROUTER_API_KEY` — ключ OpenRouter;
- `TELEGRAM_BOT_TOKEN` — токен нового рабочего бота.

Путь `TELEGRAM_SOURCE_SESSION_PATH` оставьте без изменения: рабочая Telethon-сессия будет храниться
отдельно от тестовой.

Для `TELEGRAM_WEBHOOK_SECRET` сгенерируйте случайное значение в PowerShell:

```powershell
$secretBytes = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Fill($secretBytes)
[Convert]::ToHexString($secretBytes).ToLower()
```

Скопируйте только полученную строку в `TELEGRAM_WEBHOOK_SECRET`. Это отдельный секрет, токен бота
сюда копировать нельзя. Сохраните файл и закройте Блокнот.

## 6. Загрузить настройки и создать рабочую Telethon-сессию

Сначала остановите старые окна polling и фонового планировщика сочетанием `Ctrl+C`. Затем в новом
PowerShell выполните:

```powershell
cd "C:\Users\Vladislavv\Documents\ChatGPT\AI-дайджесты бот"
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
. .\var\working-accounts-env.ps1
.\.venv\Scripts\python.exe manage.py integration_preflight
.\.venv\Scripts\python.exe manage.py init_telethon_session
```

После последней команды:

1. Telegram пришлёт код рабочему аккаунту.
2. Введите в PowerShell только сам код и нажмите Enter.
3. Если Telegram спросит пароль двухэтапной аутентификации, введите его и нажмите Enter.
4. Дождитесь сообщения `Telethon session authorized`.
5. Повторите проверку:

```powershell
.\.venv\Scripts\python.exe manage.py integration_preflight
```

В результате должны быть готовы Telethon, OpenRouter и Telegram Bot API; секреты команда не
печатает. Если есть ошибка, присылайте только вывод `integration_preflight`, без содержимого файла
`working-accounts-env.ps1`.

## 7. Провести локальную приёмку рабочего бота

Для каждого окна сначала выполните первые три строки, затем команду процесса.

**Окно 1 — админка:**

```powershell
cd "C:\Users\Vladislavv\Documents\ChatGPT\AI-дайджесты бот"
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
. .\var\working-accounts-env.ps1
.\.venv\Scripts\python.exe manage.py runserver
```

**Окно 2 — автоматический сбор, формирование и планирование:**

```powershell
cd "C:\Users\Vladislavv\Documents\ChatGPT\AI-дайджесты бот"
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
. .\var\working-accounts-env.ps1
.\.venv\Scripts\python.exe manage.py run_background_scheduler --poll-seconds 15 --local-execute
```

**Окно 3 — команды бота и отправка сообщений при локальном polling:**

```powershell
cd "C:\Users\Vladislavv\Documents\ChatGPT\AI-дайджесты бот"
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
. .\var\working-accounts-env.ps1
.\.venv\Scripts\python.exe manage.py run_telegram_polling
```

Затем откройте рабочего бота и проверьте:

1. `/start`;
2. русский и английский язык;
3. выбор одной и нескольких подборок;
4. все три частоты;
5. `/settings`;
6. `/digest`;
7. `/stop` и повторное включение подписки.

Формирование, публикация и доставка после запуска процессов выполняются автоматически. Админка
нужна для изменения справочников и просмотра состояния, а не для ручного подтверждения выпусков.

## 8. Настроить рабочий каталог в админке

На `http://127.0.0.1:8000/admin/` проверьте:

1. **Источники** — правильный URL или Telegram username, тип и активность.
2. **Подборки** — название, порядок и ключевые слова маршрутизации.
3. Связи источников с одной или несколькими подборками.
4. **Варианты частоты** — активные расписания и время в `Europe/Moscow`.
5. **Бюджеты AI по месяцам** — рабочий лимит.

Новые источники можно добавлять и включать без технической проверки. Для сайта текущая версия
рассчитывает на RSS/Atom-ленту; сайт без ленты может потребовать отдельный адаптер в коде.
Изменение расписания не переводит старых подписчиков автоматически: пользователь выбирает его
заново через `/settings`.

## 9. Что нужно сообщить для подготовки корпоративного размещения

Секреты не нужны. Пришлите одним сообщением ответы на пункты:

1. Где будет работать сервис: отдельная Linux VM, Docker-сервер или Kubernetes.
2. Версия Linux и доступные CPU, RAM и диск.
3. Адрес внутреннего Git-репозитория, куда можно отправить проект.
4. Будут ли PostgreSQL и RabbitMQ предоставлены инфраструктурой или их нужно поднять рядом.
5. Желаемый DNS-адрес админки и webhook, например `digest.company.ru`.
6. Кто выпускает TLS-сертификат и настраивает reverse proxy.
7. Как в организации хранят секреты: Vault, Kubernetes Secrets, Docker secrets или другой способ.
8. Куда складывать зашифрованные резервные копии и сколько дней их хранить.
9. Какая система логов и мониторинга используется.
10. Есть ли исходящий доступ сервера к Telegram, OpenRouter и сайтам-источникам, а также входящий
    HTTPS 443 от Telegram.
11. Кто должен иметь доступ к админке.
12. Нужно ли переносить текущий каталог и расписания из локальной базы. Рекомендация: перенести
    каталог, связи и расписания, но начать без тестовых подписчиков, тестовых доставок и AI-логов.

Пароли, токены, приватные ключи, коды Telegram и VPN-данные в этот ответ не включайте.

## 10. Что после получения этих данных выполняется в проекте

Следующий технический этап включает:

1. ограничение доступа сотрудников к рабочему боту;
2. production-конфигурацию без debug;
3. PostgreSQL и RabbitMQ;
4. HTTPS webhook Telegram и отдельный постоянный sender;
5. системный запуск web, scheduler, worker и sender после перезагрузки сервера;
6. хранение секретов вне Git и образа приложения;
7. экспорт нужной конфигурации из локальной SQLite и импорт в PostgreSQL;
8. резервные копии, внешний erasure guard и тест восстановления;
9. health checks, журналы, оповещения и контроль зависших задач;
10. миграции, проверки, короткий пилот и запуск для сотрудников.

Рабочую Telethon-сессию лучше окончательно авторизовать на корпоративном сервере. Если сначала
создать её локально, при переносе либо проводится новая авторизация, либо файл сессии передаётся
по защищённому каналу как секрет.

## 11. Ближайшее действие

Сейчас выполните разделы 2–5. После этого сообщите без секретов: username рабочего бота,
«файл заполнен» и какой вариант доступа выбран — список Telegram ID или одноразовые приглашения.
После этого выполняются разделы 6–8 и начинается подготовка корпоративного контура.
