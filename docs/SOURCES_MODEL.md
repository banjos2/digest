# Управление подборками и источниками

Это продуктовые требования к динамическому каталогу Telegram-каналов, сайтов и будущих типов источников. В каталоге сохранены 11 подборок; первая версия включает десять текстовых, а YouTube отложен пользователем. Базовые модели, локальная база, импорт, административные экраны, RSS/HTML-сбор и внутренний Telethon-адаптер реализованы. Живой Telethon-аккаунт и полный внешний AI-прогон ещё не подключены. Границы текущего модуля описаны в `README.md` и `docs/DATA_MODEL.md`.

## Сущности и связи

| Сущность | Назначение | Основные данные |
|---|---|---|
| Подборка | То, на что подписывается пользователь | Стабильный ID, slug, названия и описания RU/EN, тип выпуска, порядок, статус, наследование активного каталога расписаний, политика промптов |
| Расписание | Настраиваемый вариант частоты в меню | Стабильный ID, названия RU/EN, тип повторения, время, дни, часовой пояс, версия, видимость, состояние отправки |
| Профиль редакции или автора | Объединяет сайт, канал и языковые редакции | Название, роль, группа происхождения, редакционные замечания |
| Источник | Конкретная точка получения материалов | ID, тип, адрес, язык, профиль, настройки адаптера, статус доступа, стабильный Telegram peer_id после разрешения, состояние сбора |
| Источник в подборке | Связь многие ко многим | Источник, подборка, фильтр тем, роль, приоритет, активность, срок действия связи |
| Публикация | Один исходный материал и его версии | Идентификатор, дата, оригинальный язык и текст, каноническая ссылка, хеш, версия, сведения об авторе и первоисточнике |
| Событие | Объединяет материалы об одном событии | Подтверждённые утверждения, ссылки, происхождение, неопределённость, релевантные подборки |
| Языковая версия | RU выпуск и связанный EN перевод | Объект, язык, версия, модель, статус проверки, исходная ru_revision и хеш русского текста для EN |

В начальном JSON `profiles` представляют редакционные профили, `sources` — конкретные адреса, `source_collections` — связи. `origin_group_id` позволяет не считать сайт и канал одного профиля или его языковые редакции независимыми подтверждениями. Он не заменяет полный реестр владельцев медиа: связи собственности и синдикации уточняются отдельно.

Для источников предусмотрен `retention_policy_id`; стартовый профиль `news_default_v1` определён в `config/data_retention_policy.json`. Он хранит исходные версии и соответствующие рабочие копии 90 дней; более строгие условия источника имеют приоритет. Ссылки и хеши сохраняются на срок связанного выпуска, а удалённый исходный текст не изображается доступным доказательством.

## Требования к админке

1. Администратор создаёт подборку, задаёт русское и английское название, описание, тип, порядок и правила отбора. Подборка наследует активные варианты частоты из отдельного каталога расписаний. В черновом состоянии она не показывается пользователям.
2. Подборка активируется после проверки настроек и источников. Меню бота строится из базы; новый пункт появляется без правки обработчиков.
3. Новый источник добавляется отдельно от подборки. Администратор указывает тип и адрес, запускает диагностику и видит результат до включения постоянного сбора.
4. Один источник можно связать с несколькими подборками. Для каждой связи задаются тематический фильтр и приоритет. Сам факт связи не означает включение каждого поста во все подборки.
5. Адреса нормализуются; повторное добавление того же Telegram peer_id, RSS или канонического адреса не создаёт дубликат. Изменение username канала не создаёт новый источник.
6. Можно отключить источник глобально либо только его связь с конкретной подборкой. История опубликованных выпусков и происхождения сохраняется в пределах сроков `docs/DATA_RETENTION.md`; отключение не заменяет процедуру удаления.
7. Для профиля и публикации различаются редакционная новость, авторское мнение, заявление организации, анонс производителя, препринт и пользовательский материал.
8. В панели видны язык, последний успешный сбор, задержка, причины исключения, ошибки, успешность извлечения текста и дата технической проверки.
9. Настройки адаптеров, фильтров и промптов версионируются. Изменения администраторов записываются в журнал.
10. Импорт и экспорт каталога выполняются с предварительной валидацией и предпросмотром. Неизвестный тип адаптера не запускается молча.
11. Расписания управляются через отдельный раздел: часы, дни, названия RU/EN, создание вариантов, пауза и история изменений. На старте: дважды в день в 10:00 и 19:00, ежедневно в 13:00, по понедельникам в 13:00 — всё по Москве. Подробности в `docs/SCHEDULING.md`.

## Новые подборки и источники

Новая подборка является записью данных. Её создание, переименование, сортировка, включение и привязка существующих источников не требуют изменения кода или миграции для каждого нового названия.

Добавление Telegram-канала, поддерживаемой RSS/Atom-ленты или сайта уже поддерживаемого формата происходит через настройки. Для сайта с другой структурой, динамической загрузкой, отдельной авторизацией либо нового типа источника может потребоваться разработка адаптера. Обещание поддержки любого сайта одним URL в первую версию не входит.

Сбор и первичная обработка публикации выполняются один раз. При изменении связи «источник — подборка» уже опубликованные выпуски не пересчитываются. Повторная обработка истории — отдельное явное действие с выбранным периодом и оценкой затрат.

## Подписки пользователей

- Пользователь подписывается на стабильный ID подборки; переименование не теряет подписки.
- Добавление новой подборки не подписывает на неё всех пользователей автоматически. В меню она доступна для выбора; начальный набор для новых пользователей задаётся отдельно.
- При выключении подборки автоматическая отправка по ней прекращается. История подписки сохраняется; интерфейс объясняет её состояние.
- Замена источника внутри подборки не требует переподписки пользователей.
- Для уже опубликованного выпуска сохраняется снимок источников, правил и версий. Состав текущего каталога не подменяет происхождение старого выпуска.
- Частота хранится как стабильный `schedule_id`. Новый вариант добавляется в меню без автоматического перевода на него действующих пользователей. В первой версии одна частота применяется ко всем выбранным пользователем подборкам.
- Пользователь получает полные тематические блоки выбранных подборок в порядке каталога, с удалением повторов событий и без общего ограничения на 15 историй. Сценарии сохранения настроек, паузы, ручного запроса и доставки описаны в `docs/USER_FLOWS.md`.

## Языки

Язык источника, язык интерфейса и язык выпуска хранятся раздельно. Для первой версии языки вывода — RU и EN. Источники RU/EN входят в основной каталог; DE/FR представлены резервными источниками для проверки межъязыковой обработки.

Оригинал сохраняется. Публикации на разных языках объединяются в события с проверенными утверждениями и ссылками. Из них создаётся русский выпуск; английский выпуск — естественный перевод той же русской редакции, с теми же событиями, порядком и URL. Он не выполняет отдельный отбор для иностранной аудитории. Изменение русского выпуска делает связанный EN перевод устаревшим до обновления. Версии исходных публикаций сохраняются; изменение источника запускает проверку затронутых событий и выпусков. Пост об одном событии на двух языках не считается двумя независимыми подтверждениями.

Согласованный объём — русский дайджест по разноязычным источникам и его английский перевод. Полные переводы исходных статей и отдельный режим их чтения не являются необходимой частью этого решения. Подробные правила и формат находятся в `docs/EDITORIAL_POLICY.md`, образцы — в `docs/examples/`.

## Особенности подборки Искусственный интеллект

Подборка имеет собственный ID `ai`, RU/EN названия и подписку. Она не является простым переименованием «Технологий». Источники могут участвовать в обеих подборках с разными фильтрами.

Предлагаются темы: модели и релизы, полезные инструменты и применение, исследования, компании и инвестиции, вычислительная инфраструктура, регулирование. Количество и порядок рубрик уточняются при подготовке шаблона выпуска.

Анонс модели по возможности связывается с сообщением её разработчика. Заявленные разработчиком результаты отмечаются как его результаты, а препринт не обозначается как прошедшее рецензирование исследование без подтверждения. Рекламные посты, подборки промокодов и многократные пересказы одного релиза исключаются или объединяются.

Если событие подходит для AI, «Технологий» и «Главного», сохраняется единый event_id. Правила сборки объединённой отправки должны исключать повтор одного события при выборе нескольких таких подборок для любой частоты.

## Особенности подборки Топ YouTube

Пользователь перенёс эту подборку на следующую версию. `release_target=later_version` и `eligible_for_v1_menu=false` сохраняют запись в проектном каталоге, но исключают её из меню и генерации первой версии. Решение описано в `docs/YOUTUBE_SCOPE.md`.

Публичное [описание автора исходного бота](https://t.me/s/kolezev?before=17751) уточняет использование рейтинга YouScore и стенограмм популярных общественно-политических видео. В этой подборке сайты и Telegram-каналы из каталога служат для обнаружения видеопубликаций. Их проверка не подтверждает доступность стенограмм или рейтингов.

До реализации нужен отдельный реестр YouTube-каналов, video_id, даты публикации, язык, длительность, снимки просмотров и источник стенограммы. Для нашего рейтинга предлагается явно обозначенный выбранный пул каналов, фиксированный период и ограничение числа роликов одного автора. Не называем выборку рейтингом всего YouTube без данных для такого утверждения. YouScore и его данные не считаются автоматически доступной зависимостью нашего сервиса.

## Статусы проверки

Редакционная пригодность, техническая доступность и возможность использования разделены. Примеры технических статусов: проверена карточка канала, разобран образец RSS, получены метаданные страницы, обнаружена авторизация, получена оболочка приложения, требуется исследование доступа.

HTTP 200 не равен успешному извлечению статьи. RSS, содержащая анонсы, не гарантирует доступ к полному тексту. Публичный Telegram-канал не означает автоматического разрешения на любой вид AI-обработки. Перед включением регулярного сбора проверяется конкретный способ использования; [условия Telegram](https://telegram.org/tos/content-licensing) учитываются для соответствующих источников.

Начальный JSON хранит кандидатов неактивными, так как приложение и постоянный сбор ещё не созданы. Это состояние исследовательских данных, а не дополнительная процедура согласования для каждого последующего технического действия.

## Приёмочные сценарии для будущей реализации

| Сценарий | Ожидаемый результат |
|---|---|
| Создать и активировать подборку с RU/EN названиями | Она появляется в соответствующих языковых меню без изменения кода |
| Привязать один источник к двум подборкам | Материал собирается один раз; тематический отбор работает отдельно |
| Добавить сайт и TG того же издания | Для одного материала не возникает второго независимого подтверждения |
| Переименовать подборку или Telegram-канал | ID, подписки и история сохраняются |
| Отключить источник в одной подборке | Другие связи продолжают работать, старые выпуски неизменны |
| Добавить новую подборку | Существующие пользователи не подписываются на неё автоматически |
| Обработать одну новость на RU и EN | Получается одно событие с двумя языковыми представлениями |
| Изменить русский выпуск после подготовки EN | Английская версия помечается устаревшей; до обновления не отправляется |
| Выбрать AI, технологии и главное | Ежедневная сводка не повторяет одно событие трижды |
| Получить HTTP 200 со страницей авторизации | Диагностика сообщает об ограничении, источник не считается исправным |
| Добавить неподдерживаемый сайт | Панель объясняет необходимость адаптера, не обещает готовый сбор |
